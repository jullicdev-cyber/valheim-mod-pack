# Обновляторы Windows и Linux — 1.12.1

Причина ошибки на коммите 365cb8f: `VERSION` содержала `1.4.9`, `mods.lock.json` — `1.12.0`. Загрузка ZIP уже поддерживалась без Git; отказ происходил при сравнении этих двух полей. Исправлены метаданные выпуска и добавлена проверка согласованности в обычные Verify/Build и Linux-верификатор, чтобы проблема обнаруживалась до публикации.

Новая логика находится в `scripts/Sync-Pack.ps1` и `scripts/sync_pack.py`. Windows использует PowerShell 5.1, Python на Windows не требуется. Linux использует Python 3.9+ и стандартную библиотеку.

## Поведение

- Без Git ZIP загружается на конкретном SHA и проверяется до замены текущей папки.
- С Git, но без `.git`, подготавливается отдельный shallow clone ветки main. После проверки в ту же папку переносятся файлы и Git-метаданные с origin этой сборки; аккаунт и git user.name для этого не нужны.
- Для существующего репозитория проверяются его корень, main, отсутствие локальных изменений, ожидаемый origin и возможность fast-forward. При отсутствии origin он добавляется. Затем архив fetched-коммита проверяется до pull; pull получает именно этот SHA, даже если main успела измениться.
- Перед заменой прежние управляемые файлы сохраняются внутри .updates. ZIP-замена при исключении откатывается перемещением прежних файлов обратно. История Git принудительно не сбрасывается.
- Файлы пути к игре, пользовательские каталоги и посторонние файлы корня сохраняются. Git не перезаписывает конфликтующий неотслеживаемый файл. Параллельный запуск блокируется каталогом `.updates/update.lock`; после аварии он удаляется вручную только при закрытом обновляторе.
- Проверка кандидата предшествует установке в игру. Полный бэкап игры остаётся обязанностью прежнего установщика. `--download-only`/`-DownloadOnly` теперь обновляют папку сборки, не устанавливая её в игру.

## Проверки

`python -m unittest discover -s scripts -p test_updates.py -v`: 7 успешных тестов загрузки, безопасной распаковки, повреждённых хешей, сохранения пути и Windows PowerShell.

`python -m unittest discover -s scripts -p test_sync_pack.py -v`: 26 сценариев (13 для каждой реализации), 24 успешных, 2 пропущены из-за отсутствия разрешения на создание символических ссылок Windows. Используются реальные локальные Git-репозитории и каталоги с кириллицей и пробелами. Проверены:

- обновление ZIP без Git, повторное обновление, удаление устаревшей DLL из активной папки;
- превращение ZIP в Git-репозиторий и последующий pull нового коммита;
- сохранение настроек, музыки и посторонних файлов;
- остановка при изменённых отслеживаемых файлах, чужом origin, расхождении истории и конфликтующем неотслеживаемом файле;
- добавление отсутствующего origin;
- отклонение несовпадающей версии и повреждённого Git-кандидата до pull;
- откат после искусственно вызванной ошибки файловой замены;
- блокировка повторного запуска и отклонение персональных путей в скачанном пакете.

`python -m unittest discover -s scripts -p test_installers.py -v`: 9 сценариев, 7 успешных, 2 проверки символических ссылок пропущены по той же причине. Проверены установка, повторная установка, бэкап и откат на временных макетах игры. Настоящая папка установленной игры не изменялась.

Проверены 133 хеша и 20 пакетов сборки; Bash-обёртки прошли `bash -n`. Windows-сценарии выполнены настоящим Windows PowerShell 5.1. Linux-реализация выполнена Python на Windows; нативный Linux/Steam и реальные сетевые сбои в этих локальных сценариях не моделировались.

Старый обновлятор не умеет заменять свою исходную папку. Для перехода на новую логику нужно один раз распаковать свежий ZIP и перенести `local-settings.json`. Само исправление VERSION позволяет и старому обновлятору снова скачивать и устанавливать новые выпуски.
