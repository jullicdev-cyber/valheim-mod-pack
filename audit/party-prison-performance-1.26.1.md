# Проверка микрофризов — сборка 1.26.1

Пользователь сообщил о микрофризах каждые 0,5–1 секунду у хоста и гостя после обновления до 1.26.0. Они возникали независимо от движения и открытых окон. Проверка исходников выявила повторную работу в Party Prison 1.4.0: обслуживание экипировки каждые 0,5 секунды заново искало API Adventure Backpacks через `AccessTools.TypeByName`. Эта функция в поставляемом Harmony обходит типы загруженных сборок. Поиск выполнялся и при отсутствии рюкзаков или заключения; хост дополнительно обслуживал пять тюремных сундуков раз в секунду.

Закрытые окна World Characters и Party Prison сразу завершают обновление. Новое окно World Characters не читает заявки с диска, пока пользователь его не открывает; политика прав хоста кэшируется. Обычная запись снимков World Characters работает с прежним интервалом пять секунд, кодирование и запись выполняются в фоне.

## Что измерено

Отдельный тест использовал поставляемые Harmony, игровые DLL и моды: 170 загруженных сборок и 25 887 доступных типов. Выполнен под .NET Framework CLR, **не под Unity Mono**. Двенадцать сборок имели частично недоступные типы; соответствующая обработка ошибок может увеличивать время относительно игрового процесса. Инвентари, игровые API и нативные функции Unity не вызывались.

| Операция | Среднее время CLR | Выделенная память |
|---|---:|---:|
| Повторное определение API рюкзаков и метода | 4,08 мс | 857 109 байт за проход |
| Повторное определение API сериализации одного рюкзака | 8,52 мс | 1 735 367 байт за рюкзак |
| Чтение заранее сохранённых ссылок на API | Ниже точности вывода теста | 0 байт за итерацию |

Таким образом, только повторное определение API при двух проходах в секунду создаёт существенный временный мусор. Это подтверждённая лишняя работа и правдоподобная причина периодической сборки мусора; приведённые числа **не являются измерением FPS или продолжительности фризов в пользовательском мире**.

## Что не следует из журнала

В журнале встречались серии сохранений мира после строительства тюрьмы и рядом с загрузкой подземелья. Они не повторялись непрерывно каждые 0,5–1 секунду. Сообщение World Characters о checkpoint сопровождает нативное сохранение и само по себе не доказывает, что этот мод его запустил. Нативный `Container.Load` также сразу возвращается при неизменной версии данных сундука. Получение инвентаря Adventure Backpacks читает кэшированный компонент; сериализация вызывается только после фактического удаления временной экипировки.

Поэтому этот выпуск сохраняет прежнюю политику сохранений мира и защиты персонажей.

## Исправление

Party Prison 1.4.1 один раз связывает типизированные делегаты с API Adventure Backpacks. Типы Vapok Common берутся из той же сборки, что и API рюкзаков, чтобы не использовать независимый кэш компонентов другого мода. Обычные предметы отсеиваются до получения инвентаря рюкзака. При отсутствии или несовместимости API повторное разрешение ограничено десятью секундами; успешный результат сохраняется.

Кэш хранит только API. Содержимое и компонент каждого настоящего рюкзака читаются при каждом проходе; заменённый инвентарь не скрывается за сохранённой ссылкой. Весь ограниченный план вложенных рюкзаков строится до удаления предметов, сериализация идёт от вложенных сумок к внешним. Сохраняются прежние лимиты, частота проверки, задержка поступления нового снаряжения, правила удаления и защита личных предметов. Событийный кэш содержимого в этот выпуск не входит.

Независимая проверка успешно связала адаптер с четырьмя делегатами настоящего Adventure Backpacks/Vapok API под CLR, не вызывая игровые функции. Для того же адаптера с искусственным API проход по 40 и 120 обычным предметам не создавал выделений памяти за 100 000 повторений. Это подтверждает устранение повторного поиска и reflection-вызовов в проверяемом участке; нативный FPS остаётся отдельной проверкой.

## Удаление Adventure Backpacks

В процессе работы владелец попросил полностью исключить Adventure Backpacks. Удалены пакет из lock, DLL, переводы и исходная документация поставщика. Настройки исключений Recycle N Reclaim заменены явными пустыми правилами, чтобы мод не генерировал примерные коэффициенты разбора. Остались 109 файлов игрового пакета, 18 upstream-пакетов и 14 локальных модов; аудит DLL показывает 31 GUID и 33 сборки. Обязательных зависимостей от Adventure Backpacks нет. YamlDotNet оставлен: Jotunn непосредственно использует его десериализатор.

Проверка только чтением актуальных данных World Characters: в 13 активных состояниях и их 13 резервных файлах, а также в восьми контрольных снимках с 26 состояниями рюкзаков нет. Исторические архивы содержат рюкзаки; одна старая неодобренная заявка также содержит рюкзак. Эти данные не изменены. Сохраняются декодер вложенного содержимого и защита от отсутствующих prefab; такую заявку нельзя импортировать без предварительной разгрузки в старой сборке.

Проверка не охватывала сундуки, надгробия, предметы мира и локальные профили друзей. До установки нужно перенести содержимое рюкзаков и убрать сами предметы. Установщики Windows/Linux уже заменяют BepInEx целиком, поэтому прежняя DLL не останется рядом с новым пакетом после штатного обновления.

## Установка и проверка FPS

Полный прогон `.cache/mod-audit-576bd91f`: **42/42 набора PASS**. Проверены игровые хеши, зависимости, управляемые сценарии всех локальных модов и нативные контракты без запуска игры. Изолированные тестовые сборки без Adventure Backpacks успешно скомпилированы: Party Prison — `.cache/partyprison-native-6aee56d9`, общий QoL — `.cache/qol-native-ee1a115e`, World Characters — `.cache/worldcharacters-native-00bad2cc`. Во всех трёх ожидаемый список содержит 31 плагин и не содержит Adventure Backpacks. Старые проверки рюкзаков объявляют явный SKIP; обычные вещи, EAQS, интерфейс и защита метаданных остаются обязательными.

Точная DLL Party Prison 1.4.1: SHA-256 `62e5490c94e7d096ce02bdc7d106a55376e0307853f417ae7e9eae95d72397b2`; её копии в `local-plugins` и `Game` совпадают. Новый бинарный файл и отсутствие Adventure Backpacks в подготовленном пакете не означают, что запущенная Steam-игра уже обновилась.

Замена DLL и изолированный запуск требуют закрытого Valheim. Пользователь отложил закрытие игры. До установки новой DLL в Steam продолжает работать прежняя версия. После установки все участники должны обновиться до одной сборки и проверить неподвижное состояние, передвижение, порталы, тюрьму, выдачу и удаление временного снаряжения. Сохранение микрофризов после устранения найденной нагрузки потребует профилирования кадров именно в игровом мире.
